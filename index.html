Concept · Divide & Conquer

Break it. Solve it. Combine it.

1

Divide

Split the problem into smaller copies of itself (usually two halves).

2

Conquer

Solve each half. If it is tiny (1 element), the answer is trivial.

3

Combine

Merge the small answers into the answer for the whole problem.

Analogy: grading 100 exams. Split the pile between 2 friends, they split again… then add the totals. Each split halves the work, so there are only about log₂ n levels.

D3 · Step by step · Complexity

Three candidates, pick the max

Algorithm

  • Divide: split at the middle.
  • Conquer: best slice entirely left; best entirely right.
  • Combine: best slice crossing the middle (scan outward both ways), return the largest of the three.
  • Base case: 1 element is its own answer.

Why n log n?

T(n) = 2T(n/2) + n: two half-problems plus a linear scan for the crossing slice, over log₂ n levels.

BestAverageWorstSpace
n log nn log nn log nlog n

Same for every input: it always splits and scans.

Use it: to learn D&C, or in parallel settings. Skip it: Kadane’s single pass does the same job in O(n).

[Member 3 · ~1:15] Key trick: when merging, if we take an element from the RIGHT half, every element still waiting in the LEFT half is bigger than it, so add that many inversions. Pairs found: (2,1) (4,1) (4,3) (8,7) (8,6) (7,6) = 6.
D4 · Step by step · Complexity

Merge sort with a counter

Algorithm

  • Divide: split the array in half.
  • Conquer: count inversions inside each half (recursively).
  • Combine: merge the sorted halves; each time a right element wins, add the number of left elements remaining.
  • Total = left + right + cross.

Why n log n?

Log₂ n levels of splitting, each level merges n elements once. Brute force checks all pairs: n²/2.

BestAverageWorstSpace
n log nn log nn log nn

Extra array of size n is needed for merging.

Use it: large lists, ranking similarity, measuring sortedness. Skip it: tiny arrays, where brute force is simpler.

G1 · Why it works · Complexity

Why the greedy rule is optimal

Two-sentence proof idea

Finishing earliest leaves the most room for everything after it. Any best schedule can swap its first activity for the earliest-finishing one without losing a slot.

Complexity

BestAverageWorstSpace
n log nn log nn log n1*

Sorting by finish time costs n log n; the pick-pass is only n. *Extra space beyond the sort.

Use it: scheduling rooms, rides, CPU slots. Careful: greedy is only right when the problem allows it. Other rules (shortest first, earliest start) fail here.

Connections · When to use what

Same family, different bets

Divide & Conquer

  • Solve sub-problems, then combine.
  • Recursive, often n log n.
  • Pick it when halves are independent and merging is cheap.

Greedy

  • Commit to the best local choice, never look back.
  • Usually sort + one pass.
  • Pick it only when a proof (or exchange argument) shows it is optimal.

Link: both lean on sorting. D4 sorts while it counts, G1 sorts before it chooses.
